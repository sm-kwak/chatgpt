# Doctor Agent Lab

한 번에 **질문·검사·신체진찰 중 단일 행동**을 실행하며, 최대 60회 안에서 진단 또는 안전한 보류를 연구하는 Python 실험 프로젝트입니다. LLM은 `openai/gpt-oss-20b`용 OpenAI 호환 API를 선택적으로 사용합니다.

**연구용 합성 시뮬레이터이며 임상 의사결정 도구가 아닙니다.** 질환 이름은 실제 용어지만 확률·검사 성능·비용은 임의로 설정했습니다. 초기 연구 범위는 성인의 흉통을 가정한 5개 질환, 13개 이진 행동입니다. 이 프로젝트의 필수 검사·위험 임계값은 진료 지침이 아닙니다.

## 실행

Python 3.11 이상에서 외부 런타임 의존성 없이 실행합니다. 작업 디렉터리는 `/workspace/chatgpt`입니다.

```bash
python -m doctor_agent episode --seed 42
python -m unittest discover -s tests -v
python -m doctor_agent benchmark --cases 5000 --seed 50000 --output artifacts/heldout.json
```

실험은 실제 LLM을 호출하지 않습니다. `artifacts/`는 Git에서 제외되며 상세 행동 기록, 실패 사례의 seed, 후험확률을 저장합니다. 동일 seed의 환자는 정책이 달라도 동일한 검사 결과를 제공합니다. 저장소 파일을 자동으로 바꾸거나 Git 커밋을 만들지 않습니다.

## 의사결정과 강제 제약

1. 위험 신호를 확인하는 단일 행동을 차례로 수행합니다. 양성이면 즉시 `urgent_evaluation`으로 종료합니다.
2. 사전확률을 각 관찰 결과로 갱신합니다. 기본 선택기는 행동 비용당 기대 엔트로피 감소가 가장 큰 행동을 고릅니다. 각 관찰은 조건부 독립이라는 제한적인 가정을 사용합니다.
3. 충분한 확신에 도달한 비위험 진단도 필수 확인 행동을 마치고 잔여 위험 질환 확률이 0.5% 이하인 경우에만 `diagnosed`로 반환합니다. 기본 확신 임계값은 95%입니다.
4. 예산 또는 행동 목록이 소진되면, 위험이 임계값보다 높을 때 `urgent_evaluation`, 그 외에는 `inconclusive`로 종료합니다. 종료는 환자에 대한 추가 행동이 아닌 결과 제출입니다.

`urgent_evaluation`은 **확정 진단이나 치료가 아니라 외부 평가 요청**입니다. 의심 진단이 있으면 `diagnosis`에 포함하지만, 위험 신호만으로 종료한 경우에는 null입니다. 정확히 60회를 채울 필요는 없으며 현재 목록에서는 최대 13회만 가능합니다. 70개 행동을 가진 별도 테스트로 60회 한도도 검증합니다.

행동은 동기적으로 한 번씩 실행하며 반복하지 않습니다. 호출 전에 예산을 차감하므로 실패도 1회를 소비합니다. 잘못된 관찰이나 환경 오류는 자동 재시도하지 않고 불확실한 상태로 종료합니다. 실제 어댑터의 네트워크 호출에는 반드시 timeout과 중복 실행 방지 기능이 필요합니다.

## LLM 연동

제공자 주소가 정해지면 환경 변수로 설정합니다. `openai/gpt-oss-20b`는 모델 식별자이며 제공자를 자동으로 정하지 않습니다. 호스팅 서비스가 다른 모델 식별자를 요구하면 재설정할 수 있습니다.

```bash
export DOCTOR_LLM_BASE_URL='https://YOUR_PROVIDER/v1'
export DOCTOR_LLM_MODEL='openai/gpt-oss-20b'
# 인증이 필요하면 DOCTOR_LLM_API_KEY를 환경의 보안 설정으로 주입합니다.
python -m doctor_agent episode --seed 42 --llm
```

`/chat/completions`를 base URL 뒤에 붙입니다. HTTPS만 허용하며 로컬 모의 서버는 HTTP를 허용합니다. API 주소·인증·실제 모델 응답은 아직 검증하지 않았습니다. 키는 코드나 채팅에 넣지 마세요. 현재 전송 데이터는 합성 관찰과 진단 확률, 허용 행동뿐입니다.

LLM은 정보 기반 상위 3개 후보 중 하나를 `{"action_id":"..."}` 형식으로 제안합니다. 위험 신호 확인과 종료 판단을 바꿀 수 없습니다. 한 실행에서 adviser를 새로 생성하며 최대 5회 호출, 호출당 timeout 15초, 자동 재시도 없음이 기본입니다. 실패·시간초과·복수 행동·알 수 없는 ID는 기본 선택기로 대체됩니다. 이 제한은 환자 행동 60회와 별도로 관리합니다. LLM이 기본 선택기보다 우수하다는 근거는 아직 없습니다.

## 실제 시뮬레이터 연결

- `domain.py`: `Action`, `Observation`, `PatientEnvironment.perform(action)` 계약.
- `agent.py`: 예산·종료·안전 제약, 베이지안 갱신, 행동 선택.
- `simulator.py`: 합성 환자 생성과 임의 확률 모델.
- `llm.py`: 제한된 API 조언자와 실패 대체 처리.
- `experiment.py`: 동일 사례에 대한 정책 비교와 실패 기록.

실제 API 명세를 받으면 우선 행동 목록, 환자 초기 정보, 질문/검사 결과 형식, 완료 제출 방식, 호출 실패 과금 규칙을 대응시켜야 합니다. 현재 관찰은 이진값이므로 자유 텍스트·수치·누락값·반복 검사가 있는 실제 환경에는 관찰 스키마와 확률 모델을 확장해야 합니다. 합성 확률을 그대로 옮기면 안 됩니다. 시뮬레이터의 숨은 정답은 평가 코드만 읽고 에이전트 및 LLM에 전달하지 않습니다.

자체 데이터는 규칙 준수·회귀 테스트용입니다. 실제 평가 데이터가 확보되면 개발/검증/최종 평가 집합을 환자 단위로 분리하고, 비용·실패한 진단·긴급 평가 요청의 정의를 실제 채점 기준에 맞춰야 합니다. 실제 환경이 보류나 긴급 평가 제출을 허용하는지도 확인해야 합니다.
